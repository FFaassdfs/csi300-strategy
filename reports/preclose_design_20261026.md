> 日期：2026-10-26 ｜ 状态：**已按回测决策修订**（见 §11），预警链路实施中
> 作者：Agent + 用户 共同确认（决策点见 §2）

## 11. 决策记录（2026-10-26 回测后修订）

回测（`validate_execution_timing.py`，2020-04~2026-10-23，1570 交易日，引擎自检与 friction F0 一致）：
**整体"当日收盘执行"被否决** —— B 比 A（次日开盘）年化低 2.5pp（+17.6%→+15.1%）、Sharpe 0.82→0.71、
回撤 -16.2%→-18.4%。原因：入场信号日常出现在强势日，T+1 开盘平均比 T 收盘低（隔夜跳空均值 -0.03~-0.09%），
提前入场每笔多付负隔夜；卖出信号日常出现在大跌日，当日收盘卖在日内低点，次日开盘常有反抽。
**周末段单独看**：周五翻空 50 次中，提前到周五尾盘卖出平均好 0.02~0.17%/次（规避周末缺口）；
周五买入提前为负（芯片 2 次买贵 -2.2%）。

**用户拍板：预警保留、执行纪律不变** —— 盘中预警链路照建，但语义改为"**明日指令预告**"：
- 盘中翻空 → 预警"今日收盘大概率翻空 → 明日开盘卖出"（不改执行时点）
- 确认成立 → 预警"明日开盘买入"（不提前买入）
- 14:30 检查点 → "明日指令预览"（若收盘维持即成为明日开盘指令）
- 16:00 收盘邮件 → 新增"盘中预警回顾"（兑现/未兑现对比）+ 仍是权威
- 原设计的"当日尾盘执行 / 尾盘执行窗口 / 补登记提示"全部废弃

## 1. 背景与目标

**现行问题**：T 收盘信号 → T+1 开盘执行，自带隔夜缺口与周末缺口（周五信号拖到周一）；
实际执行经常错过开盘时点（§11.3 #18：追高买 +124bp / 尾盘杀跌卖 +235bp，累计滑点 ¥872）。

**目标**：14:30 前用实时价盘中监测信号，**状态一变就提醒、当日内操作掉**（买卖同权）；
持有为主则安静不打扰，16:00 收盘邮件统一汇报；16:00 保留为最终确认与次日开盘兜底。

## 2. 已确认决策（用户拍板）

| 决策点 | 结论 |
|--------|------|
| 执行模式 | 当日尾盘执行，**买入+卖出同权**（都提前到当日内） |
| 提醒时点 | 盘中条件触发优先（"尽量及时，而不是收盘前最后半小时才提醒"） |
| 轮询频率 | **每 30 分钟**（9:45~14:30，脚本内跳过午休） |
| 出场防抖 | **立即提醒**（第一次翻空即发），同品种同方向一天最多 2 次 |
| 午间邮件 | **取消 12:00 午间邮件**，由盘中条件提醒替代 |
| 安静模式 | 无操作不发盘中邮件；16:00 收盘邮件永远发（汇报+兜底） |
| 前瞻基准 | 14:30 实时价信号 ≈ 收盘信号（最后30分钟对 MA30/ADX/20日波动率影响极小）；14:45 太极限，14:30 留足操作窗口（用户明确） |

## 3. 回测验证（前提，先跑再落地）

新增 `validate_execution_timing.py`，R0+刹车引擎（与 `validate_friction.py` F0 同口径：2日确认、10bp、2020-04~今，基准 +17.8%/0.83/-16.2%）：

| 口径 | 信号 | 成交 | 含义 |
|------|------|------|------|
| A（现行基准） | T 收盘 | T+1 开盘 | 现行回测口径 |
| B（当日执行） | T 收盘 | **T 日收盘** | 盘中触发+当日操作的回测近似 |

**近似合法性说明**（写入报告）：真实世界盘中触发用的是当时已知的实时价（无未来函数），
成交在触发价与收盘价之间，T 收盘成交为中性近似；收盘翻空的交易日盘中几乎必然在某个
30 分钟检查点已触发（仅尾盘 15 分钟翻转例外），误差量级小。

**输出**：年化/Sharpe/回撤对比；隔夜跳空成本分解；**周末段单独统计**
（周五翻空：A=周一开盘卖 vs B=周五卖，量化缺口差异）。

**决策规则**：B 不劣于 A（年化差 ≥ -1pp 或更优）→ 落地生产链路；
B 显著更差 → 停止，回本设计重新讨论。

## 4. 生产组件：`preclose_signal.py`（新增）

### 4.1 调度与运行模式
- Windows 计划任务 `CSI300盘中预警`：**多触发时间** 9:45 / 10:15 / 10:45 / 11:15 / 13:15 / 13:45 / 14:15 / **14:30**
  （14:30 不在 9:45 起的 30 分钟网格上，需单独加一个触发；`C:\Program Files\Python312\python.exe preclose_signal.py`，纯 Python 无 shell 包装，§6.4）
- 脚本内时间窗校验兜底：9:45-11:30 / 13:00-15:00 之外（午休/盘前/收盘后）直接退出
- 单次运行流程：实时行情 → 合成K线 → 信号 → 与上次状态对比 → 条件发邮件 → 更新状态文件

### 4.2 状态检测与提醒规则
与 `reports/alert_state.json`（上次各品种信号状态 + 当日提醒计数）对比：

| 情形 | 动作 |
|------|------|
| 持仓品种翻空 | 【卖出提醒】立即发邮件：标的/份额/现价/限价提示；同品种同方向当日 ≤2 次（尾窗提醒不计入） |
| 空仓品种确认成立（昨日收盘信号=1 且本次盘中信号=1） | 【买入提醒】发邮件：金额=现金×QVIX比例×刹车权重（与 send_advice 同口径）；**同品种当日 ≤1 次**（确认成立后提醒一次，后续靠 14:30 尾窗与 16:00 邮件） |
| 持仓A翻空 且 B确认成立 | 同一封邮件内给出"卖A+买B"两条指令 |
| 14:30 检查点，当日已有未执行的操作指令 | 【尾窗提醒】发邮件强调"今日尾盘执行窗口 14:30-15:00"（**无变化不发邮件的唯一例外**） |
| 无变化 / 持有中信号持续（14:30 且无未执行指令） | 不发邮件（安静模式），只更新状态文件与日志 |

### 4.3 邮件内容规范
- 指令 + 依据（价格/MA30/ADX/波动率 vs 阈值）+ 置信度
- 每封标注：**"盘中信号可能抖动，若收盘维持以 16:00 收盘邮件为准"**
- 临界状态标注：价格距 MA30 < 0.5% 或 ADX 距阈值 < 1 → "临界，谨慎执行"
- 14:30 检查点若有未执行指令 → 邮件强调"今日尾盘执行窗口 14:30-15:00，现价附近限价单、不追高"
- 慢数据：QVIX（已有 15s socket 保护，失败跳过）；ERP 用当日缓存（`fetch_erp_percentile` 的 erp_cache）

### 4.4 数据与容错
- 实时行情：新浪 `hq.sinajs.cn` → 失败自动降级腾讯 `qt.gtimg.cn`（复用现有逻辑）
- 合成K线门控：库内无当日K线才追加实时价（与 intraday_signal 同原则，杜绝重复K线）
- 全部接口失败 → 邮件带"数据滞后"横幅或直接退出（状态文件不更新，下个检查点重试）

## 8. 风险边界

| 风险 | 对策 |
|------|------|
| 盘中信号抖动（价格贴线来回穿越） | 出场立即提醒但 ≤2 次/日 + 临界标注 + 16:00 为准 |
| 14:30 后信号翻转 | 16:00 邮件纠正，次日开盘兜底执行 |
| 尾盘操作后忘登记 | 16:00 邮件补登记提醒；balance 必填规则不变 |
| 追单滑点 | 邮件明示"现价附近限价单，不追高"（§11.3 #18 纪律） |
| 实时接口故障 | 腾讯兜底 → 全挂则退出重试，不发错误指令 |
| 非交易日误触发 | 计划任务仅工作日 + 合成K线门控（库内已有当日K线则正常计算不追加） |
